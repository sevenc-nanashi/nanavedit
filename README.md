# nanavedit

AviUtl2のスクリプト互換を目指す、クロスプラットフォームの動画編集ソフトウェアです。
現在はgpui-boxによるタイムライン・エフェクト編集画面と、Windows向けの画像・動画入力とGPU合成プレビューを実装しています。

## 開発環境

- Rust 1.99.0（`mise.toml`で指定）
- WindowsではMSVCのC++ビルドツールとWindows SDK
- Windowsの画像プレビューにはDX12対応GPUが必要です
- Linuxでは日本語フォント「Noto Sans CJK JP」
- OSごとのビルド依存は[gpui-boxの互換性ドキュメント](https://github.com/fran0220/gpui-box/blob/v0.2.0/docs/compatibility.md)を参照してください。

```sh
mise exec rust@1.99.0 -- cargo run --locked
```

gpui-box関連の依存は同じ`v0.2.0`に固定しています。

## クレート構成

Cargo workspaceで次の3クレートに分割しています。ルートは仮想ワークスペースです。`cargo run --locked`は既定メンバーの`nanavedit-app`を起動し、実行ファイル名は`nanavedit`を維持します。

| クレート | 責務 |
| --- | --- |
| `nanavedit-app`（`crates/nanavedit-app`） | GPUI、編集状態・Undo／Redo、設定、プレビューウィンドウ、非同期処理の起動・終了 |
| `nanavedit-engine`（`crates/nanavedit-engine`） | オブジェクト・エフェクト定義、フレーム評価、カメラ、GPU合成・動画テクスチャキャッシュ |
| `nanavedit-media`（`crates/nanavedit-media`） | 素材型、画像読み込み、AviUtl2入力プラグイン、動画デコード・CPUキャッシュ |

依存方向は`app → engine → media`と`app → media`です。engineとmediaはGPUIに依存しません。
`Timeline`の選択・ズーム・再生時計・履歴はアプリに残し、`Document::active_objects(frame)`で
指定フレームの有効オブジェクトをレイヤー順に取り出します。GPU描画と入力プラグインはWindows専用です。

### ウィンドウなしで描画する

利用側でDX12の`wgpu::Instance`を作り、`compatible_surface: None`でアダプターを取得します。
アプリと同様にCPUアダプターは拒否し、DeviceとQueueを作成します。
`Renderer::new(device.clone(), queue.clone(), format)`へ渡すフォーマットは、出力テクスチャと一致させてください。
出力には`RENDER_ATTACHMENT`、読み戻す場合は`COPY_SRC`も指定します。`Rgba16Float`での出力も可能です。

画像は`nanavedit_media::load_image`で読み込み、`Renderer::register_image`に素材IDとともに登録します。
動画はmediaの`Registry::new()`でレジストリと検索完了通知の送信側を取得し、`scan`に
プラグインディレクトリ・設定ディレクトリ・フォント名を渡します。検索はブロッキング処理です。
成否にかかわらず`scanning`を`false`へReleaseストアし、送信側で完了を通知してから結果を扱います。
この通知により、検索中に要求された`shutdown().await`も終了を待てます。
素材は`Registry::open(path, gpu_limits, document.settings.fps).await`で開き、`FileAsset`としてオブジェクトに設定します。

```rust,ignore
use nanavedit_engine::render::video::decode_frames;

let objects = document.active_objects(frame);
let prepared = decode_frames(&objects, frame, document.settings.fps, generation.clone(), expected_generation).await?;
renderer.prepare_video(&prepared.frames, prepared.objects)?;
renderer.settings = document.settings;
renderer.render(&objects, frame, &target_view, (1920, 1080))?;
```

`generation`は呼び出し側で保持する`Arc<AtomicU64>`です。要求を取り消すときは世代を進め、
非同期処理が返った後にも世代を比較して古い結果を破棄します。動画のないシーンでも`decode_frames`は空の結果を返します。
描画はGPUコマンドの送信まで行い、GPUの完了待ち・読み戻し・Surfaceへの表示は呼び出し側で行います。
シーンの初期値は1920×1080・30fpsで、`Document::settings`で変更できます。出力は黒背景合成で、出力サイズに合わせて縦横比を維持します。
Deviceのエラー／喪失コールバックも呼び出し側で設定し、失敗後は描画を停止してください。
プラグイン利用終了時は`Registry::shutdown().await`でワーカーとDLLの終了を待ちます。

将来のスクリプト実行は、engineの`EffectProcessor`・`ProcessContext`を利用する別クレートを追加し、
アプリ側で接続します。現在は既存の静的エフェクト登録を維持し、空のスクリプトクレートは作成していません。

## 現在の画面

- Base16テーマ（初期値はDefault Dark）、日本語表示、OS標準タイトルバー
- ウィンドウ上部の「ファイル」メニューから開く・保存・別名保存・プロジェクト設定、「設定」メニューからアプリ設定を操作
- 中央のプレビュー枠、右の設定パネル、下のタイムライン
- 境界のドラッグによる設定パネルの幅・タイムラインの高さ変更
- Tabで境界、タイムライン、操作ボタン、エフェクト設定へ移動し、境界では左右／上下の矢印キーで10論理ピクセルずつ変更
- 初期ウィンドウサイズ1280×800、最小サイズ900×600（論理ピクセル）

パネル寸法と編集内容は終了時に保存しません。音声再生、Lua/HLSL、
入力以外のプラグインの読み込み・ウィンドウ埋め込みはまだ実装していません。

## アプリ設定・配色

上部メニューの「設定」→「アプリ設定…」、またはCtrl+,で独立した設定ウィンドウを開きます。
既に開いている場合はそのウィンドウへ移動します。右側の設定パネルはオブジェクト編集用です。
設定ウィンドウを閉じても編集は続けられ、編集画面を閉じるとアプリ全体が終了します。

「YAMLを読み込む…」でBase16テーマを選ぶと、保存後すぐに両ウィンドウへ反映します。
テーマ名・作者・16色の見本を表示し、「初期配色へ戻す」でDefault Dark／Rainbowへ戻せます。
初期テーマは[Chris KempsonのDefault Dark](https://github.com/tinted-theming/schemes/blob/spec-0.11/base16/default-dark.yaml)です。

対応するYAMLは`system: base16`、`name`、`author`、`variant: dark/light`、`palette`に
`base00`〜`base0F`を持つ形式と、`scheme`、`author`、`base00`〜`base0F`を直下に持つ従来形式です。
色は引用符付きの6桁の16進数（`#`は省略可）で指定します。従来形式では背景と文字の輝度から明暗を判定します。
不正なYAML、色の欠落、Base24などの対象外形式、1MiBを超えるファイルはエラーにし、適用中の設定を保持します。
キャンセルした場合も設定は変わりません。

オブジェクトの色分けは[sevenc-nanashi/tinted-aviutl2](https://github.com/sevenc-nanashi/tinted-aviutl2/tree/main/templates)を参照しています。
Original／Rainbowを切り替えられます。クリップは単色で、背景色と種類色を通常時50%、選択時80%で混色します。

| 種類 | Original | Rainbow |
| --- | --- | --- |
| 画像ファイル | base0D | base0D |
| フィルタ | base0B | base0B |
| エフェクト | base0C | base0C |
| カメラ制御 | base0C | base0E |

設定はユーザー設定ディレクトリ内の`nanavedit/settings.json`へ保存します。
Windowsは`%APPDATA%`、macOSは`~/Library/Application Support`、Linuxは`$XDG_CONFIG_HOME`
（未設定時は`~/.config`）配下です。元YAMLのパスではなく配色そのものを保存するため、元ファイルを移動しても復元できます。
書き込み失敗時は元の保存内容と適用中の設定を維持します。保存済み設定が壊れている場合は設定ウィンドウに
エラーを表示し、YAMLの読み込みか初期配色への復帰が成功するまで編集画面を開きません。

配色は全OSで変更できます。プレビューの画像内容・合成色、OS標準タイトルバーやネイティブメニューの色は変更しません。
任意のテーマの可読性は保証しません。テーマのオンライン取得、自動再読み込み、個別の色編集は未対応です。

## プロジェクト

上部メニューの「ファイル」→「プロジェクト設定」で設定欄の表示を切り替えます。
メニュー直下の幅・高さ・fpsを入力し「設定を適用」で変更します。幅・高さは1〜8192px（GPU上限以内）、
fpsは1〜240の整数です。設定変更はUndo／Redoの対象です。既存クリップの位置・長さ・素材開始位置は
フレーム数を維持するため、fps変更で秒単位の時間が変わります。動画の素材範囲を超える変更は拒否します。

「保存」（Ctrl+S）・「別名保存…」（Ctrl+Shift+S）で`.nanavedit`形式のJSONへ保存し、
「開く…」（Ctrl+O）で復元します。設定・クリップ・エフェクト・素材の絶対パスを保存します。
素材本体・Undo履歴・選択・再生位置は保存しません。素材を移動すると読み込みに失敗します。
旧形式との互換性はありません。未保存時はプレビューに`*`を表示し、開く・終了時に破棄を確認します。
書き込みは一時ファイル経由で行い、読み込み失敗時は現在の編集内容を保持します。読み込み上限は16MiBです。

## タイムライン

初期値は30fpsで、下へスクロールすると空のレイヤーが続けて表示されます。トラック領域を右クリックして、
画像ファイル・フィルタ・エフェクト・カメラ制御の各オブジェクトを追加します。
右クリックしたレイヤー・フレーム以降で5秒分の空きがある最初の位置に追加します。
メニューを開くだけでは選択・再生位置・履歴は変わりません。
追加したクリップを選択し、その開始位置へシークします。
画像ファイルオブジェクトは未選択で配置し、設定パネルの「ファイル」からPNG／JPEGを選択します。
未選択時は透明で、タイムラインには種類名、選択後はファイル名を表示します。
「変更…」で別の画像を選べます。オブジェクト追加とファイル設定はそれぞれ別のUndo操作です。

- クリップ本体をドラッグして時間位置・レイヤーを変更し、左右端で長さを変更します。
- 空レイヤーへの配置・移動ができます。ドラッグ中は上下端で自動スクロールします。移動は1回のUndoにまとまり、Escapeで取り消せます。
- 配置と長さは1フレーム単位です。同じレイヤーでの重なりは禁止し、隣接配置は許可します。
- 移動先で重なる場合は、マウスが指すレイヤー内の最寄りの空き位置へ補正します。同距離なら時間が早い位置を選び、近ければ他のオブジェクトの反対側へ移動します。
- 左右端のドラッグは、隣接オブジェクトの境界まで伸縮します。開始は0フレーム以上、長さは最低1フレームです。
- レイヤー領域外へのドラッグは直前の有効な配置を保ちます。Escapeまたはフォーカス喪失で操作前へ戻します。
- 空白をクリックすると選択解除し、レイヤー行をクリックすると追加先レイヤーが変わります。
- レイヤーの追加操作は不要です。表示範囲の行だけ描画し、スクロールや空レイヤーの選択ではUndo履歴を増やしません。番号の大きいレイヤーが手前に描画されます。
- 設定パネルにはオブジェクト情報とエフェクト列を表示します。
- 横／縦スクロールと「−」「＋」で表示範囲を変更できます。倍率は1／2／4／8／16論理px毎フレームです。

タイムラインにフォーカスがあるときのキー操作:

| 操作 | キー |
| --- | --- |
| オブジェクト追加メニュー（選択レイヤー・再生位置） | Shift+F10 |
| 再生／停止 | Space |
| 1フレーム移動 | 左／右 |
| 先頭／最終フレームへ移動 | Home／End |
| 選択クリップを削除 | Delete／Backspace |
| 取り消し | Ctrl+Z |
| やり直し | Ctrl+Shift+Z／Ctrl+Y |
| ドラッグ取消 | Escape |

ルーラーのクリック／ドラッグでもシークできます。編集・シーク開始時には再生を停止します。
再生は経過時間に合わせて進み、最終クリップの最終フレームで停止します。
最終フレーム以降から再生すると先頭に戻ります。
Undo／Redoは最大100操作で、ドラッグ1回を1操作として扱います。
素材の読み込み中は編集操作を無効化し、失敗・キャンセルでは配置や履歴を変更しません。

複数選択、分割、コピー、境界への吸着、レイヤー削除は未対応です。

## エフェクト

各オブジェクトの設定パネルの「エフェクトを追加」メニューから「不透明度」「色反転」を追加できます。
追加順に評価し、有効／無効の切替、並べ替え、削除ができます。
不透明度は0〜100%（初期100%）で、複数指定すると乗算します。
色反転は線形RGBを反転し、アルファを保持します。2回適用すると元の色に戻ります。
スライダーと数値欄は即時反映し、ドラッグ・数値入力の一連の変更を1回のUndoにまとめます。
数値欄はEnter・フォーカス移動で確定します。数値でない入力や範囲外の値は描画へ渡さず、
確定時には最後に受理した値へ戻します。
Escapeで変更を取り消し、フォーカス移動で確定します。
設定パネルでもCtrl+Z／Ctrl+Shift+Z／Ctrl+Yを使用できます。

現在フレームで有効なオブジェクトを上のレイヤーから順に評価します。

- 入力オブジェクト：入力画像と自身のエフェクトを評価し、後続のエフェクト適用を待ちます。
- エフェクトオブジェクト：上にある最も近い入力にエフェクトを適用します。
- フィルタオブジェクト：保留中の入力を合成し、それまでの画面全体へ適用します。入力探索もここで区切ります。

次の入力・フィルタに到達するか評価が終わると、保留中の入力を画面へ合成します。
`入力A → フィルタF → エフェクトE` のEには対象がありません。
対象は現在フレームごとに決まり、対象がない場合は描画に影響せず「適用対象なし」と表示します。
入力と通常のエフェクトは元画像の解像度、フィルタはプロジェクトのシーン解像度で処理します。
出力先は画面のみです。音声、Lua／HLSL、キーフレームは未対応です。

### 標準描画とカメラ制御

画像・動画入力には固定の「標準描画」が付きます。位置XYZ・中心XYZ・各軸回転・拡大率・縦横比・
透明度・合成モード（現在は通常のみ）・カメラ制御の対象を編集できます。
標準描画は削除・並べ替えできません。描画属性を通常エフェクトの前に初期化し、
最終合成で変形するため、回転した画像を元画像の枠で切り取りません。
100%は元画像のピクセル寸法です。中心は画面中央、Xは右、Yは下、Zは奥が正です。

カメラ制御では位置XYZ・目標XYZ・傾き・視野角・対象レイヤー数を編集できます。
既定位置は(0, 0, -1024)、目標は原点です。視野角0は投影距離1024の既定値で、
正の値は垂直視野角です。対象レイヤー数0は下位の全レイヤーを対象にし、
正の値は指定した数の下位レイヤーまでを含みます。次の有効なカメラの直前で範囲を区切ります。
カメラの有効時間はクリップの開始・終了で決まります。入力は既定でカメラ対象です。

カメラ範囲内では対象入力を奥から合成し、その後に対象外の入力をレイヤー順で合成します。
交差する面はカメラ空間で分割し、半透明の部分も奥から描画します。
フィルタではそこまでの入力を合成してから画面全体を処理します。
カメラはエフェクトオブジェクトの適用先探索を変更しません。
目標レイヤー追従・焦点・深度ぼけ・カメラスクリプト・編集用カメラ・キーフレームは未対応です。

AviUtl2 2.1.14の別プロジェクトで、通常投影距離1024、中心の減算→拡大→Z/Y/X回転、
通常描画のX/Y移動が投影後であること、カメラの位置・傾き・垂直視野角、範囲境界、
後続カメラ優先、対象外入力・奥行き・交差面の重なり、裏面表示を比較しました。
近接面は投影距離の5%でクリップします。位置と目標が一致すると+Zを向き、
厳密にY軸方向を向くカメラは参照実装と同様に対象画像を描画しません。
形状の比較はプレビュー上で行っており、全条件で1シーンピクセル以内という検証は未完了です。
線形RGB合成・補間による色や境界の違いがあり、ピクセル完全一致は保証しません。

### Rustでエフェクトを追加する

`crates/nanavedit-engine/src/effects.rs` の登録一覧が、入力追加メニュー・エフェクト追加メニュー・設定UI・評価の定義元です。
`crates/nanavedit-engine/src/effects/` に定義と処理を追加し、モジュール宣言と `definitions()` の一覧に登録します。
エディターや評価ループに種類IDの分岐を追加する必要はありません。
既存の実装は `image.rs`（画像入力）、`opacity.rs`（描画属性）、`invert.rs`（GPU画像処理）を参照してください。

- `EffectInfo`：種類ID、表示名、入力／通常処理／出力設定／カメラ、パラメーター定義、時間依存の有無。
- `EffectInstance`：配置ID、種類ID、設定値、有効状態。Undo／Redoではこのデータを複製し、ファイルのリソースは共有します。
- `EffectProcessor`：種類ごとに遅延生成して共有する処理。パイプラインなどを保持でき、配置固有の設定値は `params` から受け取ります。
- `RenderParams`：不透明度・位置・中心・回転・拡大率・合成モード・カメラ対象の描画属性。
- `CameraParams`：共通の設定値から別途評価するカメラ属性。カメラは画像処理用のprocessorを持ちません。

設定値は `Integer(i32)`・`Float(f32)`・`Bool(bool)`・`Choice(&'static str)`・`File(Option<Arc<FileAsset>>)` です。
数値はSliderとNumberInput、真偽値はCheckbox、選択肢はSelect、ファイルはパス表示と選択・変更ボタンになります。
`FileAsset` はパスと読み込み済みリソースを保持します。`ParamValue` は `Clone` で複製し、GPU画像は複製しません。
`choices`で選択肢のIDと表示名、`group`で設定UIの見出しを指定します。
数値定義には範囲、刻み、表示桁数、単位を指定します。整数の範囲はSliderで正確に表せる±16,777,216以内です。
種類ID・パラメーターIDの重複、型と範囲の不整合、範囲外の既定値は起動時にエラーにします。

例えば小数と真偽値を持つ処理は、次のように定義できます（追加例であり、組み込みには含めていません）。
`crates/nanavedit-engine/src/effects/gain.rs` に置き、`crates/nanavedit-engine/src/effects.rs` に `mod gain;` と `gain::definition()` の登録を追加します。

```rust
use super::*;

pub(super) fn definition() -> EffectDefinition {
    EffectDefinition {
        info: EffectInfo {
            id: "example.gain",
            name: "不透明度倍率",
            role: EffectRole::Effect,
            param_definitions: &[
                ParamDefinition {
                    id: "gain",
                    name: "倍率",
                    default: ParamValue::Float(1.0),
                    choices: &[], group: None, file: None,
                    number: Some(NumberDefinition {
                        min: 0.0, max: 1.0, step: 0.01,
                        precision: 2, unit: "倍",
                    }),
                },
                ParamDefinition {
                    id: "bypass", name: "処理を省略",
                    default: ParamValue::Bool(false), number: None,
                    choices: &[], group: None, file: None,
                },
            ],
            time_dependent: false,
        },
        #[cfg(target_os = "windows")]
        create_processor: Some(|_| Ok(Box::new(Gain))),
    }
}

#[cfg(target_os = "windows")]
struct Gain;

#[cfg(target_os = "windows")]
impl EffectProcessor for Gain {
    fn process(
        &mut self,
        source: Option<Source>,
        params: &[Param],
        render_params: &mut RenderParams,
        _context: &mut ProcessContext<'_>,
    ) -> anyhow::Result<Source> {
        if param(params, "bypass") == ParamValue::Bool(false) {
            render_params.alpha *= param(params, "gain").number();
        }
        source.ok_or_else(|| anyhow::anyhow!("入力画像がありません"))
    }
}
```

入力は `role: EffectRole::Input` とし、`source: None` で呼ばれます。
すべての種類をパラメーターの既定値で追加します。ファイルパラメーターは
`default: ParamValue::File(None)`、`file: Some(FileKind::Image)`、`number: None`、`choices: &[]` と定義します。
画像は入力・通常エフェクトともに共通の設定UIから選択できます。
動画入力は `FileKind::Video` と `context.video(&file)?` を使います（`video.rs`参照）。
読み込みとGPU登録に成功したときだけ値と履歴を更新し、キャンセル・失敗では現在の値を保ちます。
画像処理では `param(params, "file")` の `File(Some(file))` から `context.image(&file)?` を呼び出します。
画像ファイルオブジェクトの未選択状態は `context.transparent_image()?` で1×1の透明画像を返します。
履歴の画像保持は、現在の配置とUndo／Redo内の全ファイルパラメーターを走査します。
画像の変更をUndo／Redoしてもディスクから読み直しません。

`ProcessContext` はローカル／シーンのフレーム、fps、ローカル時刻、オブジェクト／エフェクトID、
レイヤー、画面寸法とGPU操作を提供します。時間で結果が変わる処理は `time_dependent: true` を指定します。
有効な評価経路に時間依存の処理がある場合だけ、フレーム変更で再描画します。対象のないエフェクトは含めません。
処理は種類ごとに共有するため、配置固有の値やフレームをまたいで積み上がる結果を内部に保持しないでください。

GPU処理は `context.create_pipeline()` でパイプラインを初期化し、処理インスタンス内に保持します。
共通の頂点処理、`Vertex.uv`、`@group(0)` の画像・サンプラーに、独自の `fs_main` を組み合わせます。
独自のuniformは `@group(1) @binding(0)` に定義でき、`context.render()` へ16バイト単位のバイト列を渡します。
`context.acquire()` でRGBA16Floatの中間画像を取得し、乗算済みアルファの線形RGBを書き込みます。
元画像を上書きせず、使用済み入力は `context.release()` に返し、出力は所有権ごと返します。
画像を返すだけの処理では、その画像をreleaseしません。元画像のアルファ形式は `Source::premultiplied()` で確認できます。
複雑な処理ではdevice・queue・encoderにもアクセスできます。

定義は全OSで使えますが、現在の実行バックエンドはWindowsのみです。
外部ファイルからの定義／WGSL読み込み、Lua、エフェクトDLL、独自設定UI、色・文字列パラメーターは未対応です。

## 入力プラグイン・動画（Windows x64）

AviUtl2 SDK 2.1.14の入力APIを対象に、`.aui2`を読み込みます。
`%APPDATA%/nanavedit/Plugin`以下へプラグインと必要なDLLを配置して再起動してください。
起動時にサブフォルダーも検索します。設定画面の「入力プラグイン」で名前・対応拡張子・
読み込み結果を確認し、フォルダーやプラグイン自身の設定を開けます。
素材を開いているプラグインの設定は無効です。Undo履歴も素材を保持するため、設定するには再起動してください。

タイムラインの右クリックメニューから「動画ファイルオブジェクト」を追加し、ファイルを選択します。
最初の選択では素材の長さをプロジェクトのfpsへ切り上げ、次のオブジェクトに重ならない範囲で長さを設定します。
左端を縮めると素材の再生開始位置も進み、オブジェクト全体の移動では再生開始位置を保ちます。
素材の範囲を超える伸長はできません。ファイルの変更では素材の先頭へ戻し、現在の長さを新素材に収まる範囲へ縮めます。
読み込み失敗・キャンセルでは現在の素材と履歴を保ちます。シーク・再生・標準描画・既存エフェクトを利用でき、再生は無音です。

プラグインごとのワーカースレッドで呼び出しを直列化し、フレームを非同期で取得します。
必要な動画が揃うまでは直前の完成画面を保持します。再生ではデコード速度に応じて表示フレームを間引きます。
RGB24（BGR）・RGBA32（BGRA）・YUY2・PA64・HF64・YC48をGPUで線形RGBのRGBA16Floatへ変換します。
YUY2は偶数幅、BT.601のリミテッドレンジ、YC48はBT.601として扱います。
PA64/HF64は乗算済みアルファを考慮します。HDRの色管理とAviUtl2とのピクセル完全一致は保証しません。
CPU・GPUフレームキャッシュはそれぞれ256MiBのLRUです。転送バッファと同寸法の退避テクスチャを再利用します。
1フレームと同時表示する変換後フレームにも上限があり、GPUの寸法・ストレージバッファ上限を超える素材は拒否します。

`RequiredVersion`・初期化／終了・logger・configの共通APIに対応し、ログは
`%APPDATA%/nanavedit/input-plugins.log`へ出力します。共通キャッシュAPIは有効なコールバックを渡しますが、
取得・作成は空の結果／失敗を返します。これを必須とするプラグインは利用できません。
可変フレームレートの時間変換と、最初の映像トラックに対応します。
音声入力・トラック選択・D3D11テクスチャ連携・旧`.aui`・他OSでのDLL読み込みは未対応です。
DLLは同じプロセスで実行するため、プラグイン内のクラッシュやバッファ破壊はアプリにも影響します。
通常のウィンドウ終了では、処理中の要求・素材のclose・UninitializePluginの完了を待って終了します。
プラグインが応答しない場合は終了処理も待機します。

## 画像プレビュー（Windows）

再生位置で有効な画像をプロジェクトの解像度でシーンへ合成します。標準描画・カメラ制御を適用した完成画面を
縦横比を維持してプレビュー枠へ縮小し、透明部分は背面の画像へ合成します。
有効なクリップのない区間は黒く表示します。Enter／Spaceでもボタンを操作できます。

画像はバックグラウンドでデコードし、EXIFの向きを反映します。
デコード時には画像処理用の256MiBのメモリ予算とGPUの最大テクスチャ寸法を適用します。
破損・未対応形式・上限を超える画像はエラーを表示し、それまでの画像を保持します。
キャンセルした場合も画像は変わりません。

描画には子HWNDを`platform_view`で埋め込み、wgpu 30.0.1のDX12 Surfaceを使用します。
画像転送は読み込み時だけ行い、表示オブジェクトやエフェクト設定の変更、サイズ変更、Windowsからの
再描画通知に応じて描画します。再生中だけUIのフレーム更新を要求し、
毎フレームの画像転送・CPU読み戻しや常時再描画タイマーはありません。
画像は現在の配置とUndo／Redo履歴で共有し、どちらからも参照されなくなると解放します。
エフェクトは元画像を変更せず、再利用するRGBA16Floatの中間テクスチャに描画します。
不要になったサイズの中間テクスチャは解放します。保持画像と中間テクスチャの合計容量には
上限を設けていないため、大量・高解像度の画像ではGPUメモリ消費が増えます。
GPU初期化・描画の失敗は画面に表示し、ソフトウェア描画へ自動的には切り替えません。
デバイス喪失などで描画が停止した場合はアプリを再起動してください。

gpui-box v0.2.0では埋め込みホストが編集画面の背面へ配置されるため、
Windows側でホストの重なり順を補正しています。上流の修正後に取り除く予定です。

macOS／Linuxでも未選択の画像・動画ファイルオブジェクトは追加できます。
ファイルの選択ボタンは無効化し、素材の読み込み・プレビュー未対応を明示します。
パスの直接入力、ファイル変更の監視、音声ファイルの読み込みには対応していません。
